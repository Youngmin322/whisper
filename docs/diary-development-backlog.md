# Whisper 일기 방향 개발 작업 리스트

작성일: 2026-09-09 · 상태: D01 구현 완료, D02 이후 미착수

## 개발 목표와 범위

사용자가 일상, 생각, 감정, 결심을 편하게 남기고, 시간이 지난 뒤 직접 검색하지 않아도 자신의 기록을 다시 읽을 수 있게 한다. 행동 실행 여부를 핵심 성공 기준으로 삼지 않는다.

- **1차:** 기록 작성 → 보관 → 시간이 지난 기록 다시 읽기.
- **2차:** 다시 읽은 원기록에 지금의 생각을 별도 기록으로 연결하기.
- **유지:** 빠른 기록, 제목·감정·사진 선택 입력, 기존 보관함, 원문 열람, 알림 내용 미리보기 설정.
- **이번 범위에서 제외:** 분야별 실행 코칭, 강제 행동, AI 중요도·인생 패턴 분석, 새로운 집중 모드 기능, 자동 외부 기록 가져오기.
- 기존 집중 모드 연결은 호환성과 중복 알림 방지만 점검한다. 기존 데이터 구조의 대규모 이름 변경은 필수 작업에 포함하지 않는다.

## 1차 개발

### D01. 기록 단위 재발견 데이터 추가

- [x] 결심 추출 여부와 관계없이 기록을 재발견 후보로 다룰 수 있도록 새 스키마 버전을 추가한다.
- [x] 기록별 재발견 제외 여부, 일시 중지 기한, 재발견 이력을 저장한다.
- [x] 예약, 확인 가능한 노출, 실제 열람, 사용자의 명시적 제외를 구분한다. 알림 예약 시각이 지났다는 이유로 열람 처리하지 않는다.
- [x] 홈과 알림에서 같은 재발견 항목을 연결할 수 있도록 기록 ID와 재발견 항목 ID를 사용한다.
- [x] 과거 날짜 입력에 대비해 기록이 가리키는 날짜와 실제 저장·수정 시각을 구분한다. 기존 기록의 날짜는 그대로 승계한다.

**완료 기준:** 결심이 없는 일기도 후보와 이력을 가질 수 있고, 기록 날짜·저장 시각·열람 시각의 의미가 섞이지 않는다.

주요 대상: `WhisperSchema.swift`, `RecordStore.swift`

**구현 결과:** V5 스키마와 기록별 설정·만남 저장 API를 추가했다. 기록 날짜는 기존 `createdAt`으로 유지하고 실제 저장 시각은 `savedAt`에 저장한다. 이전 기록의 알 수 없는 저장 시각은 `nil`로 유지한다. 같은 만남을 다시 저장해도 열람 이력을 덮어쓰지 않으며, 원기록 삭제 시 해당 만남만 함께 정리한다. 기존 결심 설정·알림의 실제 전환과 화면 연결은 후속 작업이다.

**검증 결과:** Xcode 26.6 / iOS 26.5 시뮬레이터에서 기록 데이터·마이그레이션 테스트 12개 통과. 전체 테스트는 54개 중 53개 통과했고, 기존 `preservesCommitmentNotificationRoute()` 테스트 1개가 실패했다. 변경 전 커밋 `b647c1e`의 별도 사본에서도 47개 중 46개 통과하며 같은 테스트가 같은 원인(대기 중 기록 ID가 `nil`)으로 실패함을 확인했다. 기존 스키마 정의는 변경하지 않았다.

**로컬 환경:** 누락된 `../WhisperCore` 연결을 컴퓨터에 남아 있던 원본 패키지로 복구했다. 프로젝트의 패키지 설정은 수정하지 않았다.

### D02. 기존 데이터와 알림 전환

- [ ] 기존 기록의 ID, 원문, 제목, 사진, 감정, 날짜를 보존하는 마이그레이션을 구현한다. 과거 스키마 정의는 수정하지 않는다.
- [ ] 기존 ‘놓아주기’는 해당 원기록의 재발견 제외로, ‘쉬기’는 남은 중지 기한으로 승계한다. 기존 노출 이력도 가능한 범위에서 연결한다.
- [ ] 이미 예약된 결심 알림과 예약 관리 상태를 새 기록 기반 예약으로 교체한다. 최근 알림 이력을 승계해 업데이트 직후 같은 기록이 다시 오지 않게 한다.
- [ ] 전환 중 앱이 종료되거나 일부 저장·예약이 실패해도 다음 실행에서 중복 없이 복구한다.
- [ ] 업데이트 전에 전달된 옛 알림을 눌러도 원기록을 열 수 있도록 기존 경로를 처리한다.

**완료 기준:** 업데이트 후 기록이 유실되지 않고, 제외했던 기록이 되살아나거나 옛 알림과 새 알림이 중복되지 않는다.

선행: D01. 주요 대상: `WhisperSchema.swift`, `RecordStore.swift`, `CommitmentReminderScheduler.swift`, `WhisperAppDelegate.swift`

### D03. 일기 저장 흐름 정리

- [ ] 짧은 글만 입력해도 저장되도록 기존 빠른 기록 흐름을 유지한다. 제목·감정·사진은 선택 사항으로 둔다.
- [ ] 저장 후 표시되는 ‘이 마음을 간직할까요?’ 결심 확인 단계를 제거한다.
- [ ] 저장 시 결심을 추출하거나 기존 결심의 실행·지속 여부를 자동 판단하는 호출을 새 흐름에서 해제한다.
- [ ] 저장 성공과 실패를 분명히 표시하고, 실패 시 작성 내용을 유지한다.

**완료 기준:** 일상이나 결심 어느 내용을 쓰든 같은 흐름으로 저장되며, 추가 확인이나 AI 분석 결과를 기다릴 필요가 없다.

주요 대상: `HomeView.swift`, `QuickRecordView.swift`, `RecordFlowViews.swift`, `RecordDraft.swift`, `CommitmentAnalyzer.swift`, `CommitmentCandidateSheet.swift`

### D04. 과거 기록 수동 입력

- [ ] 기존 메모 내용을 붙여넣고 원래 날짜를 지정할 수 있게 한다. 날짜 기본값은 오늘로 둔다.
- [ ] 저장한 기록이 보관함과 상세 화면에서 지정한 날짜로 표시되도록 한다.
- [ ] 과거 기록을 여러 개 추가해도 즉시 알림을 몰아서 보내지 않고 전체 빈도 제한을 적용한다.
- [ ] 기록이 없는 상태에서는 기록 작성과 과거 기록 추가 방법을 안내한다. 사용자의 기록처럼 보이는 가짜 추억은 넣지 않는다.

**완료 기준:** 몇 달 전 메모를 입력하면 해당 날짜의 기록으로 보관되고, 사용자는 새 기록이 오래되기를 기다리지 않고 자신의 과거 기록으로 재발견 경험을 시험할 수 있다.

선행: D01, D03. 주요 대상: `RecordDraft.swift`, `RecordFlowViews.swift`, `RecordStore.swift`, `DayRecordsView.swift`

### D05. 재발견 선택 규칙과 반복 제한

- [ ] 충분히 시간이 지났고, 제외·중지 상태가 아니며, 최근 다시 건네지 않은 기록만 후보로 선택한다.
- [ ] 홈과 알림이 같은 선택 규칙과 이력을 공유하게 한다. 같은 회차의 홈 카드와 알림은 하나의 재발견으로 취급한다.
- [ ] 한 번도 건네지 않은 기록을 우선하고, 이후에는 마지막으로 건넨 시점이 오래된 기록을 우선한다. 감정이나 결심 유형으로 가치를 단정하지 않는다.
- [ ] 후보가 없으면 알림을 만들지 않는다. 기록이 적다는 이유로 같은 기록의 반복 간격을 줄이지 않는다.
- [ ] 알림을 열지 않아도 재촉하거나 빠르게 재전송하지 않는다. 미열람을 거절로 자동 해석하지 않는다.
- [ ] 미래 예약도 반복 제한 계산에 포함한다. 실제 노출 확인이 어려운 경우에도 예정 시각을 기준으로 보수적으로 재예약을 제한하되, 이를 열람으로 기록하지 않는다.

**실험용 초기값:** 기록 날짜로부터 30일 이상, 동일 기록을 다시 건네기까지 60일 이상, 전체 알림 간격 최소 7일. 검증된 최적값이 아니며, 설정과 사용 결과에 따라 변경할 수 있도록 분리한다.

**완료 기준:** 후보가 0개이면 알림이 없고, 1개이면 매주 같은 기록으로 빈자리를 채우지 않는다. 앱을 반복해서 열어도 후보가 무작위로 계속 교체되지 않는다.

선행: D01. 주요 대상: `RecordStore.swift`, `CommitmentReminderPolicy.swift`, `CommitmentReminderGlobalPolicy.swift`

### D06. 기록 기반 알림 예약과 열기

- [ ] 알림이 결심 ID 없이도 원기록을 직접 열 수 있게 한다. 홈과 알림은 같은 상세 화면을 사용한다.
- [ ] 후보와 반복 제한을 만족하는 유한한 미래 일정을 미리 예약하고, 앱 실행·설정 변경·기록 변경 시 보충하거나 갱신한다.
- [ ] 예약 가능 기간과 개수는 구현 시 정한다. 앱을 열지 않은 상태에서도 미리 예약한 여러 회차가 이어지도록 하고, 무기한 예약을 전제로 설계하지 않는다.
- [ ] 기록 삭제·재발견 제외·알림 끄기 시 관련 예약을 취소한다. 기록 수정과 미리보기 설정 변경은 남아 있는 예약 내용에도 반영한다.
- [ ] 권한 거부·철회, 시간대 변경, 예약 부분 실패, 앱 재실행을 처리한다. 권한이 없어도 기록과 홈 재발견은 사용할 수 있게 한다.
- [ ] 기존 집중 모드 알림과 일반 재발견 알림 사이에서 동일 기록이 짧은 간격으로 중복되지 않도록 공통 제한을 적용한다.

**완료 기준:** 앱을 종료한 상태에서 예정된 알림을 누르면 정확한 기록이 열리고, 제외·삭제한 기록의 새 알림이 예약되지 않는다. 여러 번 동기화해도 예약이 늘어나지 않는다.

선행: D02, D05. 주요 대상: `CommitmentReminderScheduler.swift`, `WhisperAppDelegate.swift`, `WhisperNotificationContentPolicy.swift`, `WhisperFocusFilter.swift`, `ContentView.swift`

### D07. 홈을 작성과 재발견 중심으로 변경

- [ ] ‘오늘 남기기’와 ‘다시 온 기록’을 홈의 주요 영역으로 배치한다. 이번 주 작성 횟수는 주요 영역에서 내린다.
- [ ] 재발견 카드에 원래 날짜와 원문 일부를 표시하고, 누르면 해당 원기록을 연다.
- [ ] 기록이 없음 / 기록은 있지만 아직 후보가 없음 / 다시 온 기록이 있음 상태를 각각 구성한다.
- [ ] 후보가 없을 때 최근 기록을 억지로 재발견 카드에 넣지 않는다. 보관함과 작성은 계속 이용할 수 있게 한다.

**완료 기준:** 사용자는 홈에서 바로 기록하거나 과거 기록을 읽을 수 있으며, 활성 결심이 없다는 이유로 재발견이 비어 있지 않는다.

선행: D03, D05. 주요 대상: `HomeView.swift`

### D08. 원문 열람과 보관함 정리

- [ ] 상세 화면에서 당시 날짜, 원문 전체, 첨부 사진을 중심으로 보여준다.
- [ ] 결심 실행·보관 상태 중심의 안내를 정리한다. 읽고 닫는 것만으로 흐름을 마칠 수 있게 한다.
- [ ] ‘다시 보여주지 않기’와 다시 허용하기를 제공한다. 재발견에서 제외해도 원기록은 보관함에 남긴다.
- [ ] 기존 날짜별 보관함의 조회·편집·삭제가 새 날짜 체계와 재발견 데이터에서도 작동하도록 맞춘다.
- [ ] 삭제된 기록의 옛 알림을 열면 기록을 찾을 수 없음을 안내하고 정상 화면으로 이동한다.

**완료 기준:** 홈·알림·보관함 어디서 들어가도 같은 원문을 읽으며, 재발견 제외와 기록 삭제가 분리된다.

선행: D01, D06의 알림 경로 정의. 주요 대상: `RecordDetailView.swift`, `DayRecordsView.swift`, `ContentView.swift`, `RecordStore.swift`

### D09. 설정과 앱 안내 문구 변경

- [ ] 재발견 알림 빈도를 ‘주 1회 / 2주 1회 / 끄기’로 제공한다. 주기마다 후보가 없으면 건너뛴다는 점을 설명한다.
- [ ] 알림 시간 선택과 기존 내용 미리보기 설정을 연결하고, 변경 내용을 남아 있는 예약에도 적용한다.
- [ ] 첫 안내, 홈 빈 상태, 설정, 알림에서 약속하는 가치를 ‘기록을 남기고 다시 읽기’로 통일한다.
- [ ] 기록이 재발견 대상이 되는 방식과 제외 방법을 안내한다. 기존 사용자는 업데이트 후 달라진 동작을 알 수 있게 한다.

**완료 기준:** 사용자가 언제·얼마나 자주·어떤 내용을 알림으로 받는지 이해하고 조절할 수 있다. 설정한 빈도는 최대 빈도이며, 알림 수를 채우기 위한 반복은 없다.

선행: D05, D06. 주요 대상: `ContentView.swift`, `HomeView.swift`, `WhisperNotificationContentPolicy.swift`

### D10. 출시 전 검증과 직접 사용 검증

- [ ] 기존 지원 스키마에서 최신 스키마로 전환할 때 기록·사진·날짜·제외 상태를 보존하는지 테스트한다.
- [ ] 날짜를 제어하는 테스트로 기록 0개·1개·여러 개, 모두 제외, 중지 기한, 반복 간격 경계를 검증한다.
- [ ] 예약 중복, 예약 실패 복구, 기록 수정·삭제, 설정 변경, 홈과 알림의 같은 기록 연결을 검증한다.
- [ ] 실제 기기에서 앱 종료 후 알림 열기, 권한 거부·철회, 기존 알림 열기, 장기간 앱을 열지 않은 뒤 재진입을 확인한다. 개발용 시간 단축 설정은 배포 기본값과 분리한다.
- [ ] 자신의 다양한 과거 기록으로 저빈도 사용을 시험한다. 매번 반응을 요구하는 제품 기능 대신 별도 메모로 ‘읽고 어떤 느낌이었는지 / 반복이 거슬렸는지 / 다음 기록도 받고 싶은지’를 남긴다.

**완료 기준:** 데이터 보존과 알림의 기본 동작을 통과하고, 실제 재발견 사례를 통해 다음 개선점을 판단할 수 있다. 열람 수만으로 유용성을 입증했다고 판단하지 않는다. 본인 사용 결과는 이후 사용자 검증으로 이어갈 초기 근거로 취급한다.

선행: D02~D09 통합. 주요 대상: `WhisperTests`의 마이그레이션·기록 저장·알림 정책·예약 테스트, 실제 기기

## 2차 개발

### D11. 지금의 생각 이어쓰기

- [ ] 원기록 상세 화면에 선택적인 ‘지금의 생각 남기기’를 추가한다.
- [ ] 새로운 글을 현재 날짜의 별도 기록으로 저장하고 원기록과 연결한다. 원문은 덮어쓰지 않는다.
- [ ] 원기록 상세에서 연결된 글을 날짜순으로 읽고, 새 글에서는 원기록으로 이동할 수 있게 한다.
- [ ] 보관함에서도 새 글을 해당 날짜에 표시한다. 저장만으로 새로운 알림을 즉시 보내지 않는다.
- [ ] 원기록을 삭제해도 이어쓴 글은 독립 기록으로 보존하고 끊어진 연결을 정리한다.

**완료 기준:** 당시의 글과 지금의 글을 구분해 함께 읽을 수 있고, 이어쓰기를 하지 않아도 재발견 경험이 끝난다.

착수 시점: 1차 직접 사용에서 다시 읽기의 가치를 확인한 뒤. 주요 대상: `WhisperSchema.swift`, `RecordStore.swift`, `RecordDetailView.swift`, `RecordFlowViews.swift`, 보관함
